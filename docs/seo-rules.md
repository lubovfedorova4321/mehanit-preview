# SEO-правила карточек оборудования (пилот mehanit-preview)

Правила применены к 799 карточкам `equipment-*.html`. **Не применяются** к страницам-редиректам
(«раздел переехал»), страницам категорий и подкатегорий, а также к `stock-*.html`.

## 1. H1

```
H1 = «{Тип} {Модель}»
```

- **Тип** берётся по подкатегории из хлебных крошек (словарь в §6).
- **Код поставщика** (Z, F, M, Ft, H, W, C, K, D, T, N, B, Q, S, J, X) из H1, title и description
  убирается — он остаётся только строкой артикула под H1 (§5).
- Пример: `STL18-1000 Z` → «Токарный станок с ЧПУ с наклонной станиной STL18-1000».

Частные случаи:

| Случай | H1 |
|---|---|
| 2–3 модели в карточке | тип во множественном числе + модели через запятую: «Круглошлифовальные станки MG1432, MG1350, MG1363» |
| 4+ моделей | первые три + «и др.»: «Плоскошлифовальные станки M7130A, M7140, M7140Ax1600 и др.» |
| Серия | «Лазерные станки для резки листового металла серии HG» |

## 2. title

Лесенка: берётся **первый вариант, укладывающийся в 70 символов**.

1. `{Тип} {Модель} — цена и характеристики | Механит`
2. `{Тип} {Модель} | Механит`
3. `{Тип} {Модель}` — снимается бренд
4. `{Короткий тип} {Модель} | Механит` — короткий тип только для подкатегорий из §7
5. `{Короткий тип} {Модель}`

Если не влезает и после этого — оставляем как есть. Аббревиатуры («ОЦ») не использовать.

## 3. description, 140–160 символов

```
{Тип} {Модель}: {2–3 ключевых параметра с единицами}. Поставка, ПНР, гарантия 12 мес.
```

- Параметры берутся **сначала из блока ключевых характеристик под H1**, затем из таблицы характеристик.
- Значения «под запрос» и пустые не используются, ничего не выдумывается.
- **Габаритные размеры станка и масса станка** в description не берутся.
- Повторы по значению отбрасываются («стол» и «размеры стола» с одинаковым значением — один раз).
- Если подходящих параметров нет: `{Тип} {Модель}. Поставка, ПНР, гарантия 12 мес.`

## 4. Единицы измерения в description

Только для описания; **таблицу характеристик и фильтры не менять**.

| Правило | Пример |
|---|---|
| Вт → кВт | `12000–80000 Вт` → `12–80 кВт` |
| Масса ≥ 1000 кг → тонны; меньше — килограммы | `5000 кг` → `5 т`, `750 кг` → `750 кг` |
| мм/мин → м/мин | `2000 мм/мин` → `2 м/мин` |
| м → мм | `1,5 м` → `1500 мм` |
| Десятичная запятая вместо точки | `1.0/1.3 кВт` → `1,0/1,3 кВт` |

**Параметр без единицы в таблице** — единица подставляется по названию параметра:

| Название содержит | Единица |
|---|---|
| частота вращения, обороты | об/мин |
| мощность | кВт |
| масса, грузоподъёмность | кг (или т по правилу выше) |
| высота, длина, ширина, диаметр, ход, вылет, размер | мм |

Если название не подходит под словарь — параметр не берётся.

## 5. Артикул под H1

Строка сразу под H1, стилем второстепенных подписей карточки
(`Golos Text` monospace, 11px, цвет `--muted`, разрядка .9px; класс `.sku` в `site-shell.css`).

- Одна модель: `Артикул: STL18-1000 Z`
- Несколько моделей: `Артикулы: M7130A H, M7140 H, M7140Ax1600 H, …` — полный перечень, каждая модель
  со своим кодом поставщика.
- Если кода поставщика в исходном H1 не было (6 карточек с описательным названием) — строка не добавляется.

## 9. Вывод характеристик

Правило для нового сайта: единица измерения хранится в определении параметра
(`spec-params.json`, поле `unit`), а в значении (`machines.json`, `baseSpecs[].value`)
она может быть, а может и не быть. При выводе:

| Значение в `machines.json` | Что делать | Пример |
|---|---|---|
| Голое число, диапазон или дробь из чисел | дописать `unit` из `spec-params.json` | `12` → `12 шт`, `800–1000` → `800–1000 кг`, `40/30/22` → `40/30/22 кВт` |
| Уже содержит единицу или буквенное обозначение (`мм`, `кВт`, `Ø`, `№`, `#`, `1:20`, `BT40`) | выводить как есть, `unit` не дописывать | `Ø450 мм`, `№5`, `A2-11`, `1:20` |
| `valueType: text` без `unit` | выводить как есть | `Конус шпинделя` → `ISO50` |

Проверка данных: из 63 параметров, у которых значение в каталоге без единицы, у 59 единица
задана в определении, у 4 это обозначения конусов — подробности в
[spec-units-report.md](spec-units-report.md).

## 12. Микроразметка schema.org (спецификация для нового сайта)

Раздел описывает разметку для **mehanit-site (Next.js + Payload)**. В пилот она не внедряется:
пилот закрыт `noindex` (§ «SEO: noindex для пилота»), размечать его смысла нет. Здесь зафиксировано,
что и из каких полей Payload собирать, чтобы не проектировать это заново.

Общие правила:

- JSON-LD в `<script type="application/ld+json">`, по одному блоку на сущность.
- Все URL абсолютные, на боевом домене `https://mehanit.ru`.
- Пустые значения и «под запрос» в разметку не попадают — поле просто не выводится.
- `BreadcrumbList` — на каждой странице, кроме главной; структура как в пилоте.

### 12.1. Organization — главная

`@id: https://mehanit.ru/#org`, ссылаться на него из `publisher` / `provider` / `seller`
вместо повторного описания организации.

| Поле JSON-LD | Источник |
|---|---|
| `name`, `legalName` | константа проекта: «Механит», «ООО ГК „Механит"» |
| `url`, `logo` | `NEXT_PUBLIC_SITE_URL`, файл логотипа из `public/` |
| `telephone`, `email` | страница «Контакты» (`pages`, блок контактов) |
| `address` | там же: индекс, город, улица |
| `taxID` (ИНН), `vatID` (КПП) | реквизиты со страницы «Контакты» |
| `sameAs` | ссылки на мессенджеры и соцсети из подвала |

```json
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "@id": "https://mehanit.ru/#org",
  "name": "Механит",
  "legalName": "ООО ГК «Механит»",
  "url": "https://mehanit.ru/",
  "logo": "https://mehanit.ru/mehanit-logo-cropped.png",
  "telephone": "+7 800 55 11 206",
  "email": "info@mehanit.ru",
  "taxID": "5256089670",
  "address": {
    "@type": "PostalAddress",
    "postalCode": "603123",
    "addressCountry": "RU",
    "addressLocality": "Нижний Новгород",
    "streetAddress": "Южное шоссе, д. 16 «В»"
  },
```

### 12.3. Product — карточка станка

| Поле JSON-LD | Источник в Payload (`machines`) | Правило |
|---|---|---|
| `name` | H1 карточки (§1) | «{Тип} {Модель}»; тип — из `category.typeName` |
| `sku` | `article` | «модель код поставщика», например «STL18-1000 Z». У карточек на несколько моделей и там, где `article` пуст, — **не выводить** |
| `category` | `category.title` | название подкатегории |
| `description` | `seo.metaDescription`, иначе `summary` | текст без HTML |
| `image` | `images[]` | абсолютные URL, первым — главное фото |
| `url` | `slug` + раздел | канонический адрес карточки |
| `brand` | `supplierPublicName`, иначе `brand` | **только публичное имя**. Если `suppliers.showNameOnSite = false` — поле не выводится |
| `additionalProperty` | `baseSpecs[]` | 4–8 строк, см. ниже |
| `offers` | `price` | только при `price.mode = fixed` |

**additionalProperty.** Берём 4–8 характеристик: сначала те, что в шаблоне подраздела
(`categories.specTemplate`), затем остальные по порядку. Пропускаем пустые и «под запрос».
`name` = `baseSpecs[].label` или `spec-params.name`. Значение — по правилу §9 «Вывод характеристик»:
если в `value` уже есть единица, оставляем строку как есть; если это голое число — кладём число
в `value`, а единицу из `spec-params.unit` в `unitText`.

**offers.** Выводим только когда цена реально указана: `price.mode = fixed`, `price.amount`,
`price.currency` (RUB или CNY). При `price.mode = on_request` блока `offers` нет вовсе —
придумывать цену или ставить `0` нельзя. `availability`: `InStock` при `availability = in_stock`,
`BackOrder` при `on_order`; архивные карточки не размечаем.

### 12.6. CollectionPage + ItemList — подразделы каталога

На странице подраздела: `CollectionPage` с описанием раздела и `ItemList` с карточками
первой страницы выдачи (в порядке вывода, `position` с 1).

| Поле | Источник (`categories`) |
|---|---|
| `name` | `title` |
| `description` | `seo.metaDescription`, иначе `intro` |
| `url` | `slug` |
| `itemListElement` | станки подраздела: `name` = H1 карточки, `url` = адрес карточки |

| Поле | Источник |
|---|---|
| `name`, `description` | `pages.title`, `seo.metaDescription` |
| `provider` | `{ "@id": "https://mehanit.ru/#org" }` |
| `areaServed` | «RU» |

Без `offers` и цен: стоимость сервиса считается по заявке.

### 12.8. BreadcrumbList, FAQPage, Article

Структура — как в пилоте, менять не нужно.

- **BreadcrumbList** — на всех страницах, кроме главной. `position` с 1, последний элемент —
  текущая страница, у неё `item` не указывается.
- **FAQPage** — на страницах разделов каталога, где есть блок вопросов
  (`pages.layout` → блок FAQ). Только реальные вопросы со страницы, один `FAQPage` на страницу.
- **Article** — статьи пресс-центра: `headline` = `articles.title`, `description` = `excerpt`,
  `image` = `cover`, `datePublished` = `publishedAt`, `dateModified` = `updatedAt`,
  `author` и `publisher` = организация, `mainEntityOfPage` = канонический адрес статьи.

### 12.9. Чего не делаем

- **Review и AggregateRating** — пока нет собранных отзывов с именами авторами и датами.
  Рейтинг «из воздуха» — прямое нарушение правил поисковиков и повод для ручных санкций.
- **Цены, которых нет.** Если `price.mode = on_request`, блок `offers` не выводится —
  ни с нулём, ни с «от», ни с ценой «примерно».
- **Скрытые поставщики.** Если `suppliers.showNameOnSite = false`, имя поставщика не попадает
  ни в `brand`, ни в `description`.
- **Разметка того, чего нет на странице.** Всё, что в JSON-LD, должно быть видно пользователю.

## 11. Что осталось за рамками

- `og:title` / `og:description` на карточках отсутствуют — не добавлялись, это отдельная задача.
- Числа без единиц измерения в таблицах характеристик — список в
  [`spec-values-without-units.tsv`](spec-values-without-units.tsv), правится в каталоге.
- Правила действуют **только для пилота**; в проект mehanit-site (Next.js) не переносятся.
