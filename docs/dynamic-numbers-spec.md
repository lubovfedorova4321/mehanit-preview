# Живые цифры сайта mehanit.ru — требования к переносу в CMS

Версия 25.09.2026. Относится к пилоту «Механит сайт финальная версия 01.07».

## Суть требования

На сайте есть цифры, которые зависят от количества контента: сколько статей, моделей станков, станков на складе, брендов инструмента. В пилоте они считаются скриптом `site-counters.js` из поискового индекса (`search-index.json`) и из `press-data.js`. **В CMS этих файлов не будет.** Все перечисленные ниже цифры должны считаться из базы данных при каждом показе страницы (или при публикации, с инвалидацией кэша). Переносить их как текст нельзя — они замрут.

Проверка приёмки: добавить в админке одну статью в рубрику «Внедрения», одну модель в «Токарные станки», один бренд инструмента и одну складскую карточку — все цифры из таблицы ниже должны измениться без правки шаблонов.

## Где стоят цифры и как считать

Разметка уже подготовлена: элементы помечены `data-count="…"` и `data-cat="…"`. Разработчику нужно подставлять значения в эти элементы, не меняя вёрстку.

| Страница | Элемент | Что показывает | Правило подсчёта (из базы CMS) |
|---|---|---|---|
| `press.html` | `#pressFacts [data-count="all"]` | материалов всего | статьи со статусом «опубликовано» |
| `press.html` | `#pressFacts [data-count="vnedreniya"]` | репортажей с запусков | опубликованные статьи рубрики «Внедрения» |
| `press.html` | `#pressFacts [data-count="oborudovanie"]` | разборов «как выбрать станок» | опубликованные статьи рубрики «Оборудование» |
| `press.html` | `section.rubric-section[id] .rubric-count` | «14 материалов» в заголовке каждой рубрики | опубликованные статьи рубрики, id секции = slug рубрики |
| `press.html` | `.press-latest-grid` | три свежих материала | три последних опубликованных по дате |
| `equipment.html` | `#catFacts [data-count="models"]` | моделей в каталоге | все опубликованные карточки моделей |
| `equipment.html` | `#catFacts [data-count="stock"]` | станков на складе | складские карточки со статусом «в наличии» (проданные не считать) |
| `equipment.html` | `.sol-tile-count[data-cat="turning"]` и др. | «265 моделей» на плитке категории | модели категории; `data-cat="laser,sheet,saw"` — сумма трёх категорий |
| `equipment-<категория>.html` (8 страниц) | `[data-count="cat:<slug>"]` | моделей в категории на первом экране | модели категории; `cat:laser,sheet,saw` — сумма |

| `production-equipment.html`, `production-cutting-tools.html`, `about.html` | `[data-count="brands"]` | брендов инструмента и оснастки | опубликованные страницы брендов (сейчас `brand-*.html`, 17) |
| `solution-<отрасль>.html` | `.ind-cases-grid` | три внедрения в отрасли | опубликованные статьи рубрики «Внедрения» с признаком отрасли; нужно поле «отрасль» у статьи (multi-select) |
| `press-*.html` (статьи) | блоки «Читайте также» | связанные статьи | по полям `relatedArticles` / рубрике |

Склонения: «модель / модели / моделей», «материал / материала / материалов», «репортаж / репортажа / репортажей», «разбор / разбора / разборов» — функция `pl()` в `site-counters.js`, перенести на сервер.

## Редиректы

`equipment-saw.html` в пилоте — страница-заглушка с `meta refresh` на `equipment-laser.html#subcats`. В CMS это должен быть серверный 301 (и любые другие удалённые адреса: `production-measurement`, `production-automation`, `production-coolant-chips`, `obrabotka-*` → `obrabotka-materialov-iso.html#<буква>`, `process-*` → `process.html#step-N`).

## Что НЕ считается автоматически (константы, правятся руками)

- «с 2006 года», «8 типов обработки», «12 месяцев гарантии», «выезд 1–2 дня», «8 197 ₽ нормо‑час», параметры лизинга, «1 договор / 1 ответственный» — это факты бизнеса, а не счётчики. Должны быть редактируемыми полями настроек сайта, а не зашитыми в шаблон.
- Пример расчёта стоимости обработки на странице блока инструмента (305 ₽ / 253 ₽) — иллюстрация, помечена в коде `<!-- проверить технологу -->`.

## Как устроено в пилоте (для понимания, не для копирования)

- `tools/build-search-index.py` собирает `search-index.json` / `search-index.js` — список всех страниц с категорией и url.
- `site-counters.js` (подключён на `equipment.html`, `production-equipment.html`, `production-cutting-tools.html`, `about.html`) считает модели по префиксу url `equipment-<категория>-…`, склад по `stock-…`, бренды по `brand-…`, статьи — из `window.PRESS_ARTICLES`.
- `press.html` считает свои цифры собственным скриптом из `press-data.js` (та же логика).
- `tools/build-industries.mjs` — генератор 9 отраслевых страниц; список внедрений по отраслям задан в константе `CASES` (id статей).

При переносе всё это заменяется запросами к базе; разметка и id остаются.
